# 📊 Forecasting Model Sensitivity Analysis Results

This directory contains the complete outputs of the automated sensitivity analysis pipeline, executed via `papermill`. The objective of this experiment suite is to perform a systematic and fair evaluation of multiple forecasting architectures across a variety of hyperparameter configurations. The analysis aims to demonstrate the robustness and performance of the models in different complexity scenarios, ensuring that conclusions are independent of a single architecture or parameter tuning.

---

### Workflow: From Orchestration to Insight

The files in this directory were generated by a three-step automated process, designed for parallelism, reproducibility, and detailed analysis.

| Step | Component | Role | Icon |
| :--- | :--- | :--- | :---: |
| **1. Orchestration** | `run_all_experiments_DARTS.ipynb` | **The Brain.** Generates all `(model, config)` job combinations and launches them in parallel, managing concurrency for regular and resource-intensive models. | 🚀 |
| **2. Execution** | `experiment_template.ipynb` | **The Worker.** A parameterized notebook, executed by `papermill` for each job. It trains a single model with a single configuration on all datasets and saves its results to a unique CSV. | 🤖 |
| **3. Analysis** | `analyze_results.ipynb` | **The Analyst.** After all jobs are complete, this notebook is run to load all individual result CSVs, determine the best configuration for each model, and generate the final, publication-ready tables. | 📈 |

---

### 📁 Directory Structure

This directory is organized to provide full transparency and traceability for every experiment.

| Directory | Purpose |
| :--- | :--- |
| **`notebooks/`** | Contains the executed output notebook for every single job run. This is an invaluable resource for visual inspection of plots and for debugging specific runs. |
| **`logs/`** | Contains a raw text log file for each job's `stdout` and `stderr`. Essential for diagnosing failed runs. |
| **`results/`** | The most critical output. Contains one `.csv` file per job, with detailed performance metrics for each well processed by that `(model, config)` pair. |

### ⚙️ Experiment Design

The sensitivity analysis was structured around a matrix of models and hyperparameter profiles.

#### Models Tested
- NHiTS
- N-Beats
- TiDE
- TiDE+RIN
- NLinear
- ARIMA
- AutoARIMA
- LinearRegression

#### Configuration Profiles

Each deep learning model was evaluated against five distinct configuration profiles, each with a specific goal. This ensures a comprehensive comparison, testing not just large models but also lightweight and regularized variants.

| Profile | Description / Goal |
| :--- | :--- |
| **Small & Fast** | A lightweight configuration optimized for speed and low memory usage. |
| **Medium (Balanced)** | The default, balanced configuration used for baseline results, ensuring reproducibility with original findings. |
| **Large & Robust** | A larger, more complex model designed for higher accuracy at the cost of compute resources. |
| **Stable & Regularized** | A configuration focused on high regularization (e.g., higher dropout) to prevent overfitting on noisy data. |
| **Wide & Shallow** | A configuration using wide but shallow layers to capture diverse patterns without excessive depth. |

#### Hyperparameter Grid Examples

A comprehensive grid of hyperparameters was defined for **each model and each profile** (config.py, contains all combinations). The table below shows a key representative parameter for each model type, illustrating how the profiles translate into concrete architectural changes.

| Model | Parameter | Small & Fast | Medium (Balanced) | Large & Robust | Stable & Regularized | Wide & Shallow |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **NHiTS** | `layer_widths` | 256 | 512 | 512 | 512 | **1024** |
| **TiDE** | `hidden_size` | 64 | 128 | 256 | 128 | **512** |
| **N-Beats** | `num_stacks` | 10 | 30 | **40** | 30 | 15 |
| **NLinear** | `shared_weights` | `True` | `False` | `False` | `False` | `False` |
| **ARIMA** | `(p,d,q)` | (1,0,0) | (1,1,1) | (2,2,2) | (1,0,2) |

> For the complete and detailed hyperparameter grid for all models, please refer to the `HYPERPARAM_DESCRIPTIONS` dictionary in the `config.py` file, located in the parent directory.

### How to Use These Results

To generate the final summary tables for the paper, simply run the **`analyze_results.ipynb`** notebook. It will automatically consume the `.csv` files in the `results/` folder and produce the final report.
